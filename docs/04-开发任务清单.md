# AQAOS 开发任务清单（生产级交付）

- 版本：V1.0
- 基线：SRS V2.3 / SDD V2.3 / DDD V1.3；QA-Swarm 代码快照 @7e9587d
- 性质：生产级交付的完整任务分解，含工程审计、四个开发阶段、横切运维与验收覆盖矩阵
- 用法：本清单是唯一任务事实源。开发过程中以任务 ID 沟通（Issue/Commit/PR 引用），完成状态在 §14 登记或同步至 GitHub Projects

## 1. 使用说明

- **编号规则**：`T-<Epic>-<序号>` 对应 DDD §19 的 E01–E12；`T-AUD-xx` 为审计任务；`T-OPS-xx` 为横切运维任务。
- **估算单位**：PD = 人日（1 名熟练工程师 1 个工作日）。估算含编码、单测、联调与文档，不含跨团队等待。
- **状态**：`todo / doing / blocked / done / deferred`。阶段内优先级按表格顺序（上先下后）。
- **任务粒度**：单个任务 ≤ 5 PD；超过必须拆分后才能开工。
- **变更纪律**：新增/调整任务必须同步更新 §11 覆盖矩阵，保证 FR / 验收 / NFR 三张表零缺口。

## 2. 全局 Definition of Done（每个任务通用，生产级）

1. 实现符合 SRS/SDD/DDD 契约（接口签名、枚举、错误码一致）。
2. 单元测试 + 必要集成测试通过；覆盖率不低于模块阈值（核心域 ≥ 80%，工具层 ≥ 60%）。
3. 权限校验与租户隔离（organization_id/project_id 过滤）落地，不允许绕过。
4. 审计动作写入 audit_logs（谁、何时、对什么、结果）。
5. 结构化日志 + 关键指标（OTel）+ 错误处理（统一错误码）齐备。
6. 涉及数据的变更走 Migration，可回滚，且通过 migration-check。
7. API 变更同步 OpenAPI 文档与 Dashboard 联调。
8. 禁止硬编码模型名、Secret、内部地址；配置全部外置。
9. Code Review 通过（≥ 1 名评审人）；CI 全绿。
10. 演示验收：在 Demo App（T-E01-06）上可见端到端效果。

```text
T-AUD-01 → T-E01-01 → T-E01-02/03/04（并行） → T-E01-07 → T-E01-08 → T-E01-09/10/11（并行）

```

硬性顺序约束：

1. **Anthropic 兼容端点（T-E04-02）必须先于大规模 Agent 接入**——否则会话流量绕过预算与审计（SDD §6.5 硬性要求）。
2. **契约包（T-E02-01）是一切并行的前置**——前后端/Worker 并行开发的唯一依据。
3. **Temporal（T-E03-03/04）必须先于审批（T-E03-06）与调度（T-E03-07/08）**——挂起等待与定时语义依赖持久化工作流。
4. **Qdrant→pgvector（T-E10-01）尽早决断**——一阶段记忆量小，迁移成本最低。
5. **Golden Dataset（T-OPS-06）先于大规模 prompt 调优**——否则无回归基线。
