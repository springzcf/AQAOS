## 1. 审计范围与方法

- **范围**：`packages/core/src` 全部 26 个源文件、`packages/cli/src`、`apps/api/src`、`apps/web/index.html`、`examples/demo-app`、`tests/regression`、根配置文件（package.json / tsconfig / playwright.config / .env.example / .gitignore / LICENSE）。
- **方法**：逐文件通读源码（非抽查），按以下四档判定：
  - **复用**：语义不变或微调即可迁入 AQAOS 目标位置；
  - **重构**：核心算法/结构保留，但需按目标架构改造（包位置、接口、运行时）；
  - **拆分**：文件内部分代码复用、部分丢弃；
  - **丢弃**：被目标架构中的其他机制整体取代。
- **判定基准**：SDD §5（QA-Swarm 演进映射）、SDD §6（六层运行时）、DDD §7（33 表契约）、DDD §19（Epic 归属）。

## 2. 总体结论

QA-Swarm 基线**质量高于典型开源原型**：TypeScript strict + `noUncheckedIndexedAccess` 已开启、注释解释设计意图、离线模式（MockProvider + EmbeddedVectorStore）完整、预算/隔离/只读 DB 等安全意识到位。**约 41% 代码可低成本复用，41% 可重构吸收，仅约 10% 需要丢弃**（LangGraph 适配器、Qdrant 客户端、静态 HTML 控制面）。

| 处置 | 约行数 | 占比 | 说明 |
| ---- | ------ | ---- | ---- |
| 复用   | ~2,000 | 41% | 工具域、自愈、隔离、确定性检查、提示词资产、JUnit 渲染、Demo App、回归测试 |
| 重构   | ~2,000 | 41% | 领域类型、编排、Provider、混合型 agent 逻辑、CLI、API 服务 |
| 拆分   | ~400   | 8%  | triage（启发式复用/LLM 部分重构）、store（Embedded 复用/Qdrant 丢弃） |
| 丢弃   | ~500   | 10% | langgraph-adapter、QdrantVectorStore、apps/web、in-memory 控制面 |

**关键修正**：任务清单基于"差距较大"的保守假设估算 336 PD；实际复用率偏高，E01-E06 相关任务（Runner、自愈、隔离、安全检查器、JUnit）工作量可下调约 15-20%，在里程碑复评时修正。

## 7. 处置决策（需 ADR 补录项）

- **L-1（T-AUD-02）**：采用 **MIT 为唯一许可证**（以 LICENSE 文件为准），package.json 同步改为 `"license": "MIT"`；新建 **NOTICE** 保留上游署名（QA-Swarm, Copyright (c) 2026 Bhaskar Kaphle, MIT）与本工程衍生声明。理由：LICENSE 文件的法律效力优先于 package.json 元数据，且 MIT 宽松度适合内部平台二次开发。
- **L-2**：HashEmbedder 作为**过渡嵌入器**保留至 Model Gateway embedding 端点就绪（阶段一末），届时评估切换成本，ADR 补录。
- **L-3**：D-11 的响应体送审问题升级为**安全红线用例**：会话化改造后任何 prompt 出口必须过脱敏管道（对应 T-E12-01 数据出境实现）。

## 8. 结论

1. QA-Swarm 代码库**值得作为 AQAOS 的实现基座**而非仅作参考：复用+重构合计约 90%。
2. 三个"必坏"链路（D-01/02/03）说明该基线**从未被完整端到端运行验证**，T-E01-04（CI）是首个可信度门槛。
3. 任务清单估算整体偏保守，建议 M1 完成后复评（§2 的 15-20% 下调预期）。
4. 差异清单 12 项全部闭环：8 项转 M0/M1 任务、4 项由本报告决策（L-1~L-3 + ADR-006 已覆盖项）。
